## Notes
### Operations panel (2026-10-28, 0.0.5)
- Every archive window is its own process, so jobs register in a shared folder (`app/src/ops.rs`): each running job — extract, test, create, convert, update, every archive of a batch — writes `<id>.op` (key=value) to `$XDG_RUNTIME_DIR/crate-ops/` at most every 250 ms and removes it when done; entries of processes that are gone are dropped. Pause / Resume / Cancel from the panel are a `<id>.ctl` file the job reads in its progress callback, where it also blocks while paused. Finished jobs go to `~/.local/state/crate/history` (last 200 lines). A batch's waiting archives are *queued* jobs; removing one from the panel skips it.
- Home's header has an Operations button (a dot while something runs) that opens the page (`app/ui/ops.slint`, `app/src/ops_panel.rs`, refreshed every 500 ms): Running cards (title, destination, Paused chip, percent, time left, bar, current file, processed / files / speed, Pause or Resume, Cancel), then Queued & finished (waiting jobs with Remove; history with Open / Show in folder, relative times). Header: counts, Pause all, Clear finished.
- A job that ends while its window is in the background (not focused or minimized) sends a desktop notification through `org.freedesktop.Notifications` (zbus, already in the tree for the portal; Linux only).
- Batch extract's own pause now goes through the job too, so the row and the panel agree.
- Not done: the notification's "Open folder" / "Dismiss" buttons (it's text only; listening for the action needs a long-lived D-Bus connection), Retry and Details on failed history rows, and the mockup's "Ratio so far" stat and per-job thread count.
- Tests: `ops::tests` (registry, pause/resume/cancel through the control file, history), `app/tests/ops_flow.rs` (screenshots 120–121), the panel in `a11y_flow`. Tests point `CRATE_OPS_DIR` and `XDG_STATE_HOME` at temp folders.

### Nested archives and missing volumes (2026-10-27, 0.0.4)
- **Split sets read now** (they didn't: Crate couldn't open its own `name.7z.001`). `crate_core::volumes`: `VolumeSet` finds the parts of `name.ext.001`, `name.partN.rar` and `name.rar` + `.r00` sets from any part; `Input` reads a split set as one file (positioned reads across the parts) and the ZIP, 7z and tar readers all read through it. RAR sets are read by UnRAR; Crate checks the parts in between first, and the UnRAR callback records the volume it couldn't find. The archive's size is the whole set's. Split archives can't be edited (rewriting would mean re-splitting): save a copy instead.
- **A missing part** is `Error::MissingVolume { name, part, total }`: a gap is found from the names; a missing *last* part of a 7z or ZIP from its end (the 7z start header and the ZIP end record say where it ends); a missing last RAR volume when UnRAR asks for it. The window shows "Part 2 of 3 is missing" with the parts found (size) and not found, "Locate part 2…" (a file picker; `OpenOptions.volumes` takes parts from other folders, matched by name, also handed to UnRAR when it asks) and Cancel, and reopens by itself as soon as the missing part appears in the folder (checked every 1.5 s: "Still downloading?"). Batch extract shows "Missing name" with Locate….
- **Archives inside archives** open in Crate, in a new window on the temp copy (double-click / Enter / Open), not in the desktop's default app. Edits made there come back through the existing "file open for editing" watch and "Update archive". Not done: the mockup's in-place browsing with the breadcrumb going on into the inner archive.
- **"Also unpack archives found inside"** (Extract dialog): after the extraction, `crate_core::nested::unpack` extracts each archive among the extracted files next to itself (smart folder) and removes the copy, up to 3 levels deep, each level through `Archive::extract` with all its limits. Encrypted or damaged inner archives stay as they are; the done message counts both.
- Not done: "Extract what's readable" for a set with a part missing (7z and ZIP keep their file list in the last part; only RAR could do it). The mockup's bomb and unsafe-path warnings were done in M1–M3.
- Tests: `crates/crate-core/tests/create.rs` (`split_sets_open_from_any_part`: 7z and ZIP, any part, missing middle and last part, a located part), `tests/nested.rs`, `volumes` unit tests; `app/tests/edge_flow.rs` (screenshots 110–112).

### Right-to-left spike (Slint 1.18.1, checked 2026-10-26)
Spike: `app/tests/rtl_spike.rs`. It opens an archive with the Arabic names from `MiniViewRTL.dc.html` in the real mini and full views, then draws a sheet of test cases. Captures are in [`m5-rtl/`](m5-rtl/): `real-mini-1x.png` (the real window, femtovg at 1×, dark theme), `headless-mini-2x.png`, `headless-full-2x.png`, `cases-1x.png`, `cases-2x.png`. Both femtovg and the software renderer lay out text with the same parley + harfrust code, so the results match.

**Works on its own**
- Arabic shaping: letters join, harakat and lam-alef are right, Arabic-Indic digits (٣٥٪) are fine.
- Bidi (Unicode bidi algorithm): each paragraph takes its base direction from its first strong character. So `عقود-2019.zip` displays as `zip.2019-عقود`, the same as a browser with `dir="auto"`. A path like `~/Downloads/عقود-2019/` stays LTR, with the Arabic run reordered inside it. Wrapped Arabic paragraphs break correctly.
- Font fallback: "Crate Inter" has no Arabic glyphs, so fontique asks fontconfig per script and gets the system's **Noto Sans Arabic** on Ubuntu. Spaces still come from Inter. Weight 500 renders Noto Sans Arabic *Regular*, because this Ubuntu install has only the Regular and Bold files. Next to Inter Medium, Arabic text therefore looks lighter.
- A font the app registers itself is *not* used for fallback. Tested by registering Noto Naskh Arabic in the spike: the system Noto Sans Arabic still won. A `Text` takes one `font-family`, followed by the generic families only, with no family list.
- Window titles in Arabic are fine (checked under XWayland).

**Has to be done by hand**
- **No layout mirroring.** Slint has no layout-direction setting. `HorizontalLayout` always places children left to right (case "HorizontalLayout"). `FlexboxLayout { flex-direction: rtl ? row-reverse : row; flex-wrap: no-wrap; }` does mirror, and its direction can change at runtime (case "Flexbox row-reverse"). Elements placed with `x:` need `rtl ? parent.width - self.width - x : x`.
- **`horizontal-alignment: start` isn't direction-aware.** The docs say it follows the text direction, but `i-slint-core/textlayout/sharedparley/layout.rs` maps `Start` to parley `Left` (and `End` to `Right`). Arabic text with the default or `start` alignment sits on the left. Every `Text` and `TextInput` (the search field too) needs `horizontal-alignment: Locale.rtl ? right : left`.
- **`overflow: elide` is broken for RTL lines.** No "…" is drawn and the line spills out of its box to the left, over the tile and other neighbours (see the long name in `real-mini-1x.png` and the "elide" cases). The elision code walks glyphs left to right in visual order and assumes the line's end is on the right. This hits Arabic file names in the *English* UI too, so it's a bug today, not only in M5. Reported upstream as [slint-ui/slint#14434](https://github.com/slint-ui/slint/issues/14434) (2026-10-26; minimal case rendered in `m5-rtl/elide-repro.png`). When it's fixed, `ClipText` can go back to a plain `Text`. Worked around (2026-10-26): every line that starts with a file, folder or archive name goes through `ClipText` (`app/ui/parts.slint`), a clipping box around an eliding `Text`. The name now stops at its cell edge, still without a "…" (`real-mini-1x-clipped.png`). Left-to-right names elide as before. `rtl_spike` checks that the mini view's gutter stays clean. Use `ClipText` for any new name cell.
- Directional icons (chevrons, the `→` in sizes, breadcrumb `›`, back) must be swapped by hand in RTL.

They are renamed by `scripts/rename-font-family.py`, because the OFL reserves the name "Plex" for modified copies. It's the font the mockups use, its weights match the UI's 500/600, and it has its own Latin set.

"Crate Arabic" : "Crate Inter"`. Arabic file names in the English UI keep using the system fallback (Noto Sans Arabic on Ubuntu). The spike's "Crate Arabic 500/600" cases show it.

### Translations and the Arabic UI (done 2026-10-26)
What was built, and where it differs from the proposal below:
- **One catalog, two readers.** `.slint` strings use `@tr()`, bundled at build time (`with_bundled_translations`, no default context, so "Cancel" is one entry). Text built in Rust uses `i18n::tr / trf / trn` (`app/src/i18n.rs`); `build.rs` compiles the same `.po` into a lookup table. This replaces the proposed `Strings` global: Slint globals belong to one window, and helpers such as `model::size_text` run with none. `model::count(n, "item")` maps to real plural forms; sizes, durations and dates are translated too (`{month} {day}, {year}`, ك.ب).
- **Adding strings:** mark them, then `scripts/update-translations.sh` (slint-tr-extractor 1.18.1 + a scan for `tr(` / `trf(` / `trn(` in `app/src`, then `msgmerge`). Never build sentences by concatenation; use `{}` / `{name}` slots and plural forms.
- **Arabic catalog** (`app/translations/ar/LC_MESSAGES/crate-app.po`): 433 strings, 6 plural forms, «» quotes, ٪, ← in "A ← B". Inserted names and paths are wrapped in FSI … PDI (U+2068/U+2069) so a Latin name keeps its own direction («project/», not «/project»). Format and checksum names (ZIP, CRC32…) stay untranslated on purpose.
- **Direction:** `Locale.rtl` is `@tr("default:LTR") == "default:RTL"` (GTK's convention), so every window follows the selected translation without Rust wiring. Windows use "Crate Arabic" as their font in Arabic.
- **Mirroring with GridLayout, not Flexbox.** `FlexboxLayout` (row-reverse) caused binding loops wherever it sat in a `VerticalLayout` (its height depends on its width), and flipping the window with `transform-scale-x: -100%` is not drawn by the software renderer and breaks FemtoVG's clip rectangle. Rows with two or more children are a `GridLayout` whose children take `col: Locale.rtl ? (last - i) : i; row: 0` (absent `if` children are left out of the numbering, otherwise they cost a column of spacing). Rows with `alignment:` keep an outer `HorizontalLayout` whose start/end swaps; unequal left/right padding swaps; `x:` placements use `Locale.rtl ? parent.width - self.width - x : x` (bars fill from the right, switches are on at the left, the level slider runs right to left). Text without an explicit alignment uses `Locale.start`. Directional icons are `Icons.chevron-back / chevron-forward / arrow-back`; Left/Right keys in the preview and the grid follow the reading direction.
- **New rows:** with two or more children, write them as such a `GridLayout` (see any row in `mini-view.slint`); single-child rows can stay `HorizontalLayout`.
- English is pixel-identical to before except two rows the old layout got wrong or that `GridLayout` sizes a little differently: the breadcrumbs (no longer spread apart when there are several) and the Properties stats row (about 20 px). `arabic_flow` saves 70–77-ar-*.png.
- **Not done / known gaps:** messages that come from `crate-core` errors, encoding names ("Arabic (Windows-1256)") and the preview's language names stay in English; `ClipText` still has no "…" for RTL names (Slint #14434); the language switch applies at once only to the windows of the process that changed it. Headless tests use the software renderer: the real window (FemtoVG) still needs the hand check in Acceptance.

**Proposed approach for `@tr()` and gettext** (superseded in part, see above)
- Mark strings in `.slint` with `@tr()`, with plurals as `@tr("{n} item" | "{n} items" % n)`. Extract them with `slint-tr-extractor` into `app/translations/crate-app.pot`, with `app/translations/ar/LC_MESSAGES/crate-app.po` for Arabic (Arabic has 6 plural forms).
- **Bundle the translations** (`slint_build::CompilerConfiguration::with_bundled_translations("translations")`) instead of the runtime `gettext` feature. Nothing to install in `share/locale`, the same in AppImage, Flatpak, Windows and macOS, and no libintl. Slint picks the bundled language from the system locale on its own. `slint::select_bundled_translation("ar")` switches it at runtime, for the Preferences language setting.
- Slint has no public API to translate a string from Rust (`translate` is in `private_unstable_api`). About 120 `format!` calls in `app/src` build text, so text the user sees moves into a Slint global with pure functions, e.g. `Strings.extracted(n, name)` with `@tr` inside. Rust calls `invoke_extracted(…)`, so there's one catalog for both sides.
- Add a `Locale` global (`rtl: bool`, set from Rust from the chosen or system language). Every mirrored layout, alignment and icon reads it, as described above.
